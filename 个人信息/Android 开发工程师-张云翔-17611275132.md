## 项目经历

### 组件化架构改造

**背景**
Keeta 上线节奏快，工程耦合重、依赖不清，扩展与分工成本高，需做模块化/组件化，支撑后续并行迭代。

**措施**

1. 按业务边界与复用拆 Module，以「职责拆分 + 单向依赖 + 公共下沉」消除交叉引用。
2. 页面跳转走注解路由（编译期路由表 + 路径映射），去掉对具体 Activity 的硬依赖。
3. 跨组件能力走「接口下沉 + 服务注册/发现」，依赖抽象不依赖实现。
4. `includeBuild` + `dependencySubstitution` 支持组件源码/AAR 切换，便于联调。
5. 组件独立打包上传 Maven，壳工程按 GAV 聚合，发版互不影响。

**收益**
工程依赖清晰、团队可按组件分工并行；降低耦合带来的联调与冲突成本。

### 启动耗时优化

**背景**
观测到 Keeta 启动偏慢，海外机型与网络偏弱，影响首屏体验。

**措施**

1. **启动任务编排**：任务抽象为 Task，按依赖生成 DAG，多线程按优先级执行；低优任务结合 IdleHandler 空闲执行；子线程预加载 SP，主线程走内存。
2. **定位提前**：权限授予后即发起定位，缩短首页等待。
3. **围栏参数本地化**：QGIS 简化围栏后内置 JSON；定位后用 MBR + 射线法命中 cityId/region，减少启动期串行接口。
4. **首页地址缓存**：经纬度截断作 Key 缓存物理地址，命中则启动即可展示。

**收益**
沙特地区 7 日均值对比：启动 4.31s → 3.14s，约 30%。

### 包体积优化

**背景**  
Keeta 面向海外分发，包体影响下载转化。对 Apk 按 dex、资源 so 拆解分析后，代码、资源与 so 均有瘦身空间；其中部分 so 非启动强依赖，适合改为远程下发，并配合发版体积管控防止回弹。

**措施**
1.**包体分析**  
 使用 Android Studio Analyze APK、ApkTool 定位体积大户，按代码、资源、so 分类制定优化项。
2.**代码与依赖瘦身**  
 Release 开启 `minifyEnabled`（混淆 / 压缩 / 优化）与 ProGuard 规则治理；统一网络、图片等基础库，收敛重复依赖；优先更小或可裁剪引入的三方库，清理无用代码。
3.**资源瘦身**  
 开启 `shrinkResources` 移除未引用资源；图片转 WebP 并压缩；本地多密度收敛；非必要本地图改为网络下发。
4.**SO 动态下发（dynLoader）**

- 编译期（Gradle 插件）：配置需动态下发的 so / assets；插件在构建时将其从安装包中剥离，按 abi（仅 `arm64-v8a`）打包并计算 version、MD5；自动生成资源清单并与 so 包一并上传 CDN；正式 Apk 不再打入这些 so，从而直接减包体。
- 启动后：按 CDN 清单异步预下载；本地已有且 version + MD5 校验通过则复用，否则下载、校验、解压到私有目录，将文件先准备就绪。
- 进入使用场景：业务页调用时再 `System.load` 本地 so 绝对路径；预下载未完成则等待下载成功后再加载，失败则降级或重试。
5.**长期治理**  
 发版组件体积设阈值，超限必须优化后再合入，避免体积回弹。

**收益**  
从约 85 MB → 约 75 MB，下降约 13%。
