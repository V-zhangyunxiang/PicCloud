# 熟悉思路

目标可以压成一句话：**先顺着插屏一条链读通，再单独抠「谁赢谁输」的比价。**

Poseidon 不是「各家 SDK 各自为政」，而是：

> 宿主调门面 → 场景解析策略 → 各 mediation 加载进缓存池 → **按 eCPM 比价取胜者** → 展示 → 点击/关闭回调 → paid 收入上报

## 全流程脑图（插屏）

```text
初始化
  PoseidonAPI.register → PoseidonSetupProcessor.register
  PoseidonAPI.initialize → platformInitialize
       ├─ 读/解密 PoseidonConfig
       └─ TopOn / AdMob / MAX init

预加载 / 加载
  PoseidonAPI.loadInterstitialAd
    → AdFlow.loadInterstitialAd（特殊场景分流）
    → PoseidonAPIProcessor.platformPreload
         ├─ 解析 scene → strategy → placements
         ├─ 频控 / 压力熔断等门禁
         └─ 调 mediation *Load → 成功写入 Cache（带 eCPM）

展示（比价发生在这里）
  PoseidonAPI.showInterstitialAd
    → PoseidonAPIProcessor.platformShowFullscreenAd*
         ├─ 从 strategy 缓存 / shared ceil-floor / automation 等池取出候选
         ├─ 包装成 Bidder 列表
         ├─ selectTopBidder / compareTo（按 eCPM 等排序）
         ├─ winner.notifyWin()，其他人 notifyLoose()
         └─ 调对应 *Show → 三方 SDK 展示

展示后链路
  onAdImpression / onPaidEvent → AdPaidInfo → Firebase + Adjust
  onAdClicked → adv_click + 宿主回调
  onAdClosed / dismissed → adv_hide + 可能触发下一次 preload
```

## 「比价」在 Poseidon 里到底指什么

别和「单家 SDK 内部 bidding」混为一谈。Poseidon 这边你要抓的是：

1. **加载阶段**：多家（TopOn/AdMob/MAX）可以各自加载、进不同缓存池。  
2. **展示前**：把可用候选收成 `Bidder` 列表。  
3. **排序**：`CacheAd.compareTo` → `compareCacheAdRank`（核心字段是 `eCPM()`）。  
4. **结算**：最高价 `notifyWin` 去 show；其余 `notifyLoose`（销毁或回池，看具体实现）。

所以读比价时，**优先精读这 4 个点**，比把三个 mediation 目录全扫一遍更有效：

- `Cache.kt` / `CacheAdRankingResolver.kt`
- `bid.kt`
- `PoseidonAPIProcessor` 里 show 路径的 bidder 组装
- 各网 `eCPM()` 实现（例如 `AdmobInterstitialShow` / `TopOnInterstitialShow` / `MaxInterstitialShow`）

## 实操技巧（比「通读仓库」快）

1. **IDE 从 API 往下追**：对 `loadInterstitialAd` / `showInterstitialAd` 做 Call Hierarchy，不要从 mediation 叶子往上猜。  
2. **一次只跟一个 sceneName**：例如 demo 里某个固定 scene，对照 `PoseidonConfig` 的 `pos_scene` → `strategy_id` → placements。  
3. **日志关键字**：搜 `LogHub` / `platformShowFullscreenAd` / `consumeCacheAd` / `selectTopBidder`，真机打一条插屏，日志能把比价候选和 winner eCPM 对上。  
4. **事件地图**：`doc/poseidon-sdk-event-map.md` 用来对「点击/关闭/收入」埋点，代码里对着 `adv_*` reporter 读。  
5. **先忽略**：压力熔断、新用户特殊 preload、通知开屏——主链通了再回来看 `CriticalPressureBreaker`、`restrict/`、`main/preload/`。
