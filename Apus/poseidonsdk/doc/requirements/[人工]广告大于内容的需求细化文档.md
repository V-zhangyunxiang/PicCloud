广告大于内容时的限制广告展示的需求细化

整体注意：不能限制广告加载，只能限制广告展示，因为加载往往是在一个或几个页面时，就提前进行了。

一、技术方案实现：
1、基础json参考文档：/Users/zhougejie/AdProjects/ads-boost/flynk_config/library/flynk_6.0.1.json。

2、在广告策略的全局开关中，增加ad_restriction_by_content:false。（初版默认为false，云控开）
添加位置：global_control -> ad_restriction_by_content。
注意：它不受global_control -> frequency_switch 全局频控总开关影响，作为一个完全独立的功能，可以单独开启或关闭。

3、在具体场景的广告配置下，加上page字段，来标识当前广告场景所在的页面名称。
成本增加：后续每次提供广告配置时，需要结合APP的广告内容，合理标记页面信息。（需要和李沐、产品对应的技术负责一起定好）

4、内存态存储的数据结构：（以下所有的广告类型，都是场景配置的预期的广告类型）
last_page: 标识上个页面
current_page: 标识当前页面
last_inter_show_count: 0 (初始值)
last_native_show_count: 0 (初始值)
last_reward_show_count: 0 (初始值)
last_app_open_show_count: 0 (初始值)
last_banner_show_count: 0 (初始值)
current_inter_show_count: 0 (初始值) 
current_native_show_count: 0 (初始值)
current_reward_show_count: 0 (初始值)
current_app_open_show_count: 0 (初始值)
current_banner_show_count: 0 (初始值)

注意：每次进入下一个页面时，都需要current前缀的对应广告类型的字段赋值给last前缀的对应广告类型的字段。

2、案例逻辑推演
【进入主页页面，假设前一个页面0个广告】
last_page: null、""或"null"均代表上一页为空，即无广告展示
current_page: main_page

进入主页：
showAd("main_page_inter")
展示成功，
current_inter_show_count + 1

当前主页下：
showAd("main_page_native")
展示成功，由于是原生类型，用户在当前页面比如看新闻流的话，
可能存在下拉滚动不断去调用showAd("main_page_native")或showAd("xxxx_native")，

第1次展示成功：current_native_show_count + 1 
【重要逻辑，预期广告类型为原生时，原生展示多次，也只算一次】
第2次展示成功：current_native_show_count不变

if(current_native_show_count == 0) 
	current_native_show_count + 1 
else 
	current_native_show_count 保持不变

当前主页下
showAd("main_page_banner")
展示成功，由于是Banner类型，可能存在同位置隔一段时间，不断加载和展示新的广告，比如Banner轮播、新广告替换旧广告。

第1次展示成功：current_banner_show_count + 1 
【重要逻辑，预期广告类型为Banner时，Banner展示多次，也只算一次】
第2次展示成功：current_banner_show_count不变

if(current_banner_show_count == 0) 
	current_banner_show_count + 1 
else 
	current_banner_show_count 保持不变

【进入下一个页面】
last_inter_show_count: current_inter_show_count赋值到此
last_native_show_count: current_native_show_count赋值到此
last_reward_show_count: current_reward_show_count赋值到此
last_app_open_show_count: current_app_open_show_count赋值到此
last_banner_show_count: current_banner_show_count赋值到此
current_inter_show_count: 重置0 
current_native_show_count: 重置0
current_reward_show_count: 重置0
current_app_open_show_count: 重置0
current_banner_show_count: 重置0

进入祷告页：
showAd("pray_page_inter")

last_page: main_page
current_page: pray_page

last_page: pray_page
current_page: answer_page

再进入答题页：		
showAd("answer_page_reward")

由于前一页祷告页最多只有一个插屏展示，所以进入答题页，
根据上述逻辑判断，一定能展示答题页的插屏广告。

【广告大于内容的核心限制逻辑】
if(前一页的已展示广告总数+当前页的已展示广告总数) > 2
	不允许展示广告，增加新的ADPV打点，错误类型为广告大于内容。
	(复用原有的打点事件，只是增加一个新的错误码和错误信息)
else
	允许展示广告，广告展示是否成功？
		未成功展示，不处理。
		已成功展示，current_inter_show_count + 1

【补充逻辑1】
当前页，已经出现广告大于内容的限制了，但广告内容中的预期广告展示类型，如果包含了原生或Banner类型，可以继续展示广告。（因为占位相同）

【补充逻辑2】
前一页如果0个广告，当前页达到3个广告后，第4个预期为非原生或非Banner类型的广告，将不再允许进行新广告展示，但不影响广告加载。
