广告频控策略的需求细化文档

一、增加新的三级组合的广告频控策略：
1、全局广告的频控策略：
1.1 概要定义：所有任意的广告都需要满足此策略的限制。
1.2 具体策略，在Json中的定义和字段：
(1) 广告频控总开关，是否开启广告频控能力，true代表开启，false代表关闭。
在json中的位置，flynk.json -> global_control -> frequency_switch
(2) 广告最大展示次数，广告在一天内达到最大展示次数后，不再允许展示广告。
在json中的位置，flynk.json -> global_control -> max_displays
(3) 广告最大点击次数，广告在一天内达到最大点击次数后，不再允许展示广告。
在json中的位置，flynk.json -> global_control -> max_clicks
(4) 广告展示最小间隔，单位为秒，代表任意两个广告之间的最小展示间隔时长，小于该值时，不再允许展示广告。
在json中的位置，flynk.json -> global_control -> min_interval

2、分广告类型的广告频控策略：
2.1 概要定义：不同广告类型(比如插屏、开屏等)的广告都需要满足此策略的限制。
2.2 具体策略，在Json中的定义和字段：
(1) 插屏最大展示次数，插屏广告在一天内达到最大展示次数后，不再允许展示广告。
在json中的位置，flynk.json -> ad_type_controls -> interstitial -> max_displays
(2) 插屏最大点击次数，插屏广告在一天内达到最大点击次数后，不再允许展示广告。
在json中的位置，flynk.json -> ad_type_controls -> interstitial -> max_clicks
(3) 插屏最小间隔时长，代表任意两个插屏广告之间的最小展示间隔时长，小于该值时，不再允许展示广告。
在json中的位置，flynk.json -> ad_type_controls -> interstitial -> min_interval
(4) 开屏最大展示次数，开屏广告在一天内达到最大展示次数后，不再允许展示广告。
在json中的位置，flynk.json -> ad_type_controls -> app_open -> max_displays
(5) 开屏最大点击次数，开屏广告在一天内达到最大点击次数后，不再允许展示广告。
在json中的位置，flynk.json -> ad_type_controls -> app_open -> max_clicks
(6) 开屏最小间隔时长，代表任意两个开屏广告之间的最小展示间隔时长，小于该值时，不再允许展示广告。
在json中的位置，flynk.json -> ad_type_controls -> app_open -> min_interval
(7) 原生最大展示次数，原生广告在一天内达到最大展示次数后，不再允许展示广告。
在json中的位置，flynk.json -> ad_type_controls -> native -> max_displays
(8) 原生最大点击次数，原生广告在一天内达到最大点击次数后，不再允许展示广告。
在json中的位置，flynk.json -> ad_type_controls -> native -> max_clicks
(9) 原生最小间隔时长，代表任意两个原生广告之间的最小展示间隔时长，小于该值时，不再允许展示广告。
在json中的位置，flynk.json -> ad_type_controls -> native -> min_interval
(10) 激励视频最大展示次数，激励视频广告在一天内达到最大展示次数后，不再允许展示广告。
在json中的位置，flynk.json -> ad_type_controls -> rewarded -> max_displays
(11) 激励视频最大点击次数，激励视频广告在一天内达到最大点击次数后，不再允许展示广告。
在json中的位置，flynk.json -> ad_type_controls -> rewarded -> max_clicks
(12) 激励视频最小间隔时长，代表任意两个激励视频广告之间的最小展示间隔时长，小于该值时，不再允许展示广告。
在json中的位置，flynk.json -> ad_type_controls -> rewarded -> min_interval
(13) Banner最大展示次数，Banner广告在一天内达到最大展示次数后，不再允许展示广告。
在json中的位置，flynk.json -> ad_type_controls -> banner -> max_displays
(14) Banner最大点击次数，Banner广告在一天内达到最大点击次数后，不再允许展示广告。
在json中的位置，flynk.json -> ad_type_controls -> banner -> max_clicks
(15) Banner最小间隔时长，代表任意两个Banner广告之间的最小展示间隔时长，小于该值时，不再允许展示广告。
在json中的位置，flynk.json -> ad_type_controls -> banner -> min_interval

注意：当前json配置中，没有flynk.json -> ad_type_controls -> rewarded时，代表
激励的广告间隔时长、展示、点击频次上没有限制，但在广告展示时，仍然要记录激励广告展示的时间戳，方便其他类型广告的频控判断。

3、分场景的广告频控策略：
2.1 概要定义：广告SDK调用方在调用广告展示API时，传入的具体广告场景的广告，都需要满足此策略的限制。
2.2 具体策略，在Json中的定义和字段：
(1) 具体广告场景的最大展示次数，改广告场景的广告在一天内达到最大展示次数后，不再允许展示广告。
在json中的位置，flynk.json -> scenes[] -> max_displays
(2) 具体广告场景的最大点击次数，改广告场景的广告在一天内达到最大点击次数后，不再允许展示广告。 
在json中的位置，flynk.json -> scenes[] -> max_clicks
(3) 具体广告场景的最大展示次数，改广告场景的广告在一天内达到最大展示次数后，不再允许展示广告。
在json中的位置，flynk.json -> scenes[] -> min_interval

二、加载广告阶段的频控策略的使用（Load Ad）
调用loadAd的API(placementName, adType)
    ↓
检查频控开关（flynk.json -> global_control -> frequency_switch）
    ↓
如果关闭 → 直接通过，允许加载
    ↓
如果开启 → 判断(当前调用Load的时间戳 - 比对的时间戳) 是否大于24小时？
大于等于，则把当前时间更新到比对的时间戳，同时对各项计数累计的值均重置为初始值。
小于，则不进行任何处理。
    ↓
按以下顺序检查：
1. 检查全局频控
COUNT全局展示次数是否超限？
COUNT全局点击次数是否超限？
全局MAX(display_time) 与当前时间的间隔是否过短？
2. 检查类型频控
COUNT类型展示次数是否超限？
COUNT类型点击次数是否超限？
类型MAX(display_time) 与当前时间的间隔是否过短？
3. 检查场景频控
COUNT场景展示次数是否超限？
COUNT场景点击次数是否超限？
场景MAX(display_time) 与当前时间的间隔是否过短？
    ↓
任何一层不通过 → 返回拦截结果
    ↓
全部通过 → 返回允许加载
    ↓
如果拦截 → Debug下的上报日志，不加载广告时增加广告失败的相关打点。
如果通过 → 按原有逻辑，正常加载广告到缓存。

三、展示广告阶段的频控策略的使用（Show Ad）
调用showAd的API(placementName, adType)
    ↓
检查频控开关（frequency_switch）
    ↓
如果关闭 → 直接通过，允许展示
    ↓
如果开启 → 判断(当前调用Show的时间戳 - 比对的时间戳) 是否大于24小时？
大于等于，则把当前时间更新到比对的时间戳，同时对各项计数累计的值均重置为初始值。
小于，则不进行任何处理。
    ↓
按以下顺序检查：
1. 检查全局频控
COUNT全局展示次数是否超限？
COUNT全局点击次数是否超限？
全局MAX(display_time) 与当前时间的间隔是否过短？
2. 检查类型频控
COUNT类型展示次数是否超限？
COUNT类型点击次数是否超限？
类型MAX(display_time) 与当前时间的间隔是否过短？
3. 检查场景频控
COUNT场景展示次数是否超限？
COUNT场景点击次数是否超限？
场景MAX(display_time) 与当前时间的间隔是否过短？
    ↓
任何一层不通过 → 返回拦截结果
    ↓
如果拦截 → Debug下的上报日志，不加载广告时增加广告失败的相关打点。
如果通过 → 缓存获取广告并展示，在收到展示成功的回调后，按需更新全局、类型、场景的展示次数，更新最新一次展示时间戳，方便统计展示间隔时长。
    ↓
4.广告是否发生了点击？
如果点击，在收到点击成功的回调后，按需更新全局、类型、场景的点击次数。
如果未点击，则不进行任何处理。
