Poseidon SDK Runtime Dossier

Source-verified runtime behavior map for the shipped Android SDK in this repository. The goal of this dossier is breadth first and then detail: host contract, startup, config control plane, load/show orchestration, preload families, restrictions, mediation adapters, analytics, persistence, native crypto, and current runtime edge cases.

This document prefers active source over older repo notes. Where repo notes and code diverged, the active code path wins and the knowledge base was updated in the same task.

Public Contract

register → initialize → load/show
The host-facing contract is a static facade on PoseidonAPI, backed by a single registered PoseidonSetupProcessor instance on the main thread.

Core Runtime Shape

Hub + Processor + Pools
Loads route through AdFlow, shows through PoseidonAPIProcessor, and cache/search spans main strategy cache plus shared, automation, new-user, notification, and scene-backup pools.

Main Risk Surface

Config, gating, fallback
Externally visible behavior is dominated by config resolution, frequency/show/CTR gating, client-side bidder selection, and no-cache fallback rules.

1. Runtime Topology

The runtime is not a single straight line. It is a control plane plus several parallel state domains. PoseidonAPIProcessor is the orchestration center, but it relies on setup state, config singletons, preload families, and mediation wrappers that continue mutating shared state after startup.

2. Host Contract And Runtime Inputs

2.1 Public entrypoints

Surface Runtime effect Notes
register(PoseidonSetupProcessor) Atomically installs the singleton setup instance. Main thread only. Also warms first-open tracking.
initialize() Starts remote listeners, reconnect watcher, consent startup, show-limit cleanup, attribution refresh, TopOn grouping, lifecycle callbacks, and mediation init. Main thread only.
loadInterstitial/Open/Rewarded/NativeAd() Dispatches off caller thread into the load routing graph. All public load calls background-dispatch before work begins.
showOpen/Interstitial/Rewarded/NativeAd() Runs gate-first show orchestration and returns a Cancelable. No-cache live-load branches are lifecycle-cancelable.
loadAndShowBannerAd() Runs immediate banner load+show and returns a Destroyable. Banner is not cached.
hasCacheAd() Queries live in-memory cache domains. Not just config presence; expired entries are pruned.
doOnPrivacyOptionsIsRequired() / showPrivacyOptionsForm() Routes into the GDPR/CMP subsystem. Availability callback and actual UI show are separate paths.

2.2 Setup processor constructor inputs

  • application: root context for Room, mediation init, UMP, lifecycle callbacks, network monitoring, and asset access.
  • firebaseRemoteConfigProvider: lazy provider wrapped by FirebaseCloudImpl.
  • mainActivityClass: host main activity reference, used by lifecycle callbacks to auto-show the GDPR/CMP consent form when that exact activity resumes.
  • poseidonSharedPreference: overridable SpHelper for state persistence.

2.3 Build-type and flavor runtime variance

Axis Behavioral effect
debug POSEIDON_DEBUG_SWITCH=true; local JSON/property overrides are enabled; Napier debug logging is enabled; several parse/setup failures crash instead of only reporting.
qa Inherits release-like behavior but forces POSEIDON_DEBUG_SWITCH=true; TopOn preset strategy can still be enabled.
release Debug override paths are disabled; embedded release ad config asset is used as a local baseline against Firebase.
Flavor (lumina, ember) Injects flavor-specific embedded release config asset name, AdMob app id, and maticoo_app_key through Gradle.

5. Runtime State Domains

5.1 In-memory domains

  • Main strategy cache. Strategy placements loaded through platformLoadAd(), keyed by ad unit id plus per-strategy placement mapping.
  • Shared pools. SharedCeilAdPool and SharedFloorAdPool, each with its own cache list and request/failure counters.
  • Automation pools. CeilAutomation and FloorAutomation, recurring preloader caches.
  • New-user caches. One manager per (adType, mediation) bucket.
  • Notification splash cache. Single interstitial cache with separate counters for failure, fill count, and request interval.
  • Specific-scene backup cache. Global interstitial-only pool filtered by supported scene names at query time.
  • CMP form cache. Cached consent form plus atomic guards for show exclusivity.
  • TopOn attribution cache. Volatile cached channel/campaign plus last-sent values inside coordinator.

5.2 Persistent domains

  • SharedPreferences. Device id, first-open timeline, CTR flags, notification counters, shared-pool counters, automation counters, specific-backup counters, attribution cache, RRC/AEO one-shot flags, fullscreen interval timestamp, CMP Europe cache.
  • Room tables. AdLimitShowInfo, adExtraInfo, AdFrequencyStats.
  • Assets / external files. Embedded release ad config asset, debug JSON overrides, local Firebase property overrides, TopOn test properties.
  • Native library state. JNI cryptor, fixed AES key/IV, CRC32 flow-control engine.

6. Load Behavior

6.1 Generic loader pipeline

flowchart TD
    PublicLoad[Public load API]
    Bg[dispatchToBackground]
    Route[AdFlow routing]
    Preload[platformPreload]
    Analyze[platformLoadAdWithAnalyzer]
    Gate[platformLoadAd gates]
    Resolve[resolveScene]
    Waterfall[Strategy waterfall recursion]
    Create[createXxxAdLoader]
    InitGate[mediation init gate]
    Mode[AdLoadModeControl]
    NetLoad[mediationAdLoad]
    Cache[cache on success]
    Stats[UnitResponseTracker + BizAdResponseTracker]

    PublicLoad --> Bg --> Route --> Preload --> Analyze --> Gate --> Resolve --> Waterfall --> Create --> InitGate --> Mode --> NetLoad --> Cache
    NetLoad --> Stats
  • All public load entrypoints background-dispatch before doing routing.
  • AdFlow diverts notification splash and new-user scenes before ordinary strategy loading.
  • platformLoadAd() gates on global switch, network availability, ad-impression-limit load gate, scene resolution, and unified load-frequency control.
  • The actual loader path always checks mediation readiness before calling into the third-party SDK.
  • TopOn has an extra hook: every TopOn load calls TopOnTrafficGrouping.callBeforeTopOnAdLoad(adUnitId) first.

6.2 Waterfall semantics

  • The strategy waterfall is success-chained, not parallel fan-out.
  • Placement recursion begins at the lowest freshness/priority index and only advances deeper on success, so later placements are fresher in cache.
  • Cross-type conversion is allowed. A requested fullscreen type can load placements of other fullscreen types or native and later convert at show time.
  • If a placement is already cached, the waterfall treats that as success and continues deeper with loadCallback=null for later placements.

6.3 Load traffic control

Mode Decision Runtime behavior
immediate RunImmediately Calls the loader directly.
serial EnqueueSerial FIFO queue, one active load session at a time.
delay ScheduleDelay(delayMillis) If another ad is loading, waits and can be woken up early when the current load completes.
Source-verified nuance. modeDefault="delay" does not imply delayed behavior by itself. If modeDelay is missing, the implementation falls back to serial queueing. The unit tests explicitly lock this in.

7. Preload Families

7.1 Shared pools

Pool Number Input config Distinct behavior
SharedCeilAdPool 3 PoseidonConfig.sharedCeil Higher-eCPM shared inventory checked in all fullscreen/native auctions.
SharedFloorAdPool 1 PoseidonConfig.sharedFloor Lower-tier shared inventory checked when floor participation is enabled.
  • CAS-guarded to one concurrent preload run per pool.
  • Gates on global switch, network, and ad-impression-limit load gate.
  • CacheKey can deduplicate by any cache, by ad type, or by ad unit id.
  • Maintains per-ad-unit consecutive failure counters and daily request counters in SharedPreferences.
  • MAX "No Fill" failures decrement the daily request counter back down.

7.2 Shared-pool trigger matrix

  • After any ad load response.
  • At every call-show entry.
  • On impression.
  • On failed-to-show.
  • On dismiss.
  • On explicit app-startup helper.
  • On notification shown or clicked preload entry.
  • On network reconnect.

7.3 Automation

  • CeilAutomation default interval 30s; FloorAutomation default interval 20s.
  • Each recurring cycle tries all TopOn units plus the first AdMob unit as top-level candidates.
  • If top-level candidates all fail, the system retries the second AdMob unit, then the first AdMob unit.
  • Per-ad-unit failure counters reset daily with computeDailyCounterPlan().

7.4 New-user managers

  • One manager per (adType, mediation) bucket.
  • Only interstitial and rewarded are used.
  • Fullscreen consume priority is global: MAX rewarded → MAX interstitial → AdMob rewarded → AdMob interstitial.
  • Each manager keeps a single cached wrapper and returns it to the manager if it loses the auction.

7.5 Notification splash preload

  • Always triggers shared-pool preload first.
  • Then applies configuration check, ad-impression-limit check, cache check, daily failure-count check, daily fill-unused check, request-interval check, and network check before actual load.
  • Display-triggered preload updates last-request time; click-triggered preload resets some counters first.
  • The main notification cache is a single interstitial wrapper.

7.6 Specific-scene backup

  • Recurring 5-second loop once started.
  • Implementation is interstitial-only even though the config model is not strongly typed that way.
  • Cache pool is global; supported scene names are enforced only at query/consume time.

8. Show Behavior

8.1 Fullscreen gate order

  1. Global switch.
  2. Unified show-frequency check.
  3. AdShowLimitConfigProcessor.check(sceneName).
  4. AdShowLimit.canShowAd().
  5. CtrLimit.canShowAd().
  6. FullscreenAdImpressionIntervalLimit.canShowAd().

  8. Network availability unless offline show is explicitly allowed.

  • Notification splash scenes have a special branch: if client bidding is disabled in notification config, only the notification-main ad participates and all other reserved bidders are restored immediately.
  • Non-notification fullscreen scenes use the scene's enableClientBidding flag; if false, only the main strategy cache participates.

8.3 No-cache fallback

Scene flags Outcome
allowNoCacheRequest=false Fail immediately with ERROR_CODE_NO_CACHE_DISALLOWED_LOAD. If allowNoCachePreload=true, background-preload anyway.
allowNoCacheRequest=true Start live load via LifecycleCancelableAdLoader; on success re-query cache and show immediately.

8.4 Native show

  • Gates on global switch, unified show frequency, ad-impression-limit show gate, CTR, and network/offline flag.
  • No fullscreen interval limit applies.
  • Bidder sources are smaller: ceil, ceil automation, main, floor, floor automation.
  • On native impression the scene may auto-preload again if allowPreloadWhenNativeAdImpressed is enabled.

8.5 Banner show

  • No caching and no bidding.
  • Still checks global switch, ad-impression-limit show gate, network, load frequency, and show frequency.
  • Banner wrappers do not implement a meaningful ready-handle contract; BannerAdBase.isReady() is unsupported.

8.6 Native mixed into fullscreen

  • Native wrappers can win fullscreen auctions and are displayed through a dedicated fullscreen host activity instead of a mediation-owned fullscreen UI.
  • Entry points: showNativeMixInterstitialAd, showNativeMixRewardedAd, showNativeMixOpenAd.
  • Rewarded native mix auto-grants RewardItem.UNKNOWN on close.
Current runtime defect. NativeMixOpenAdActivity is currently miswired: its start() stores open refs, but the shared base activity only reads interstitial and rewarded statics, so the open variant exits at the null guard instead of rendering.

9. Restriction Systems

9.1 Unified frequency

  • Three levels: global → ad type → scene.
  • Show-time pipeline runs new-user first-cold-start check, then content-balance check, then frequency check.
  • Load-stage interval checks log but do not block; show-stage interval checks can block.
  • Room-backed counters use Beijing day keys and purge data older than 3 days on day rollover.

9.2 New-user first cold start

  • Eligibility is session-scoped and initialized once.
  • Fresh-install detection uses installTime == updateTime.
  • First-open timeline is separate and persisted during register().
  • Scenes with firstShow=false can be blocked before ordinary frequency checks.

9.3 Content balance

  • Pre-show gate for show frequency only.
  • Tracks per-page ad counts with single-count protection for native and banner.

9.4 Show-limit families

  • Global AdShowLimit. Counts only AdMob/Facebook impressions for daily cap.
  • Scene AdLimitShowCfg. Room-backed per-scene windowing logic with a (rowId, canShow) check result and later updateShown(rowId).

9.5 CTR

  • Counts clicks per session.
  • Can force-close the ad activity and can also mark the daily limit as reached.
  • Daily reset uses local date helper, not Beijing time.

9.6 Fullscreen interval limit

  • Can scope limited ad types separately for close recording and show checking.
  • Uses either flat interval or day-based interval map keyed from first-open age.
  • Uses system timezone for day math, not Beijing timezone.

9.7 Traffic sampling

  • TrafficLimit is separate from load-mode traffic control.
  • Uses device-local persisted id plus native CRC32 sampling to gate diagnostics and other sampled flows.

10. Mediation Families

10.1 Initialization behavior

Family Init characteristics Notable runtime quirks
TopOn ATSDK.init(appId, appKey); network debug logs follow POSEIDON_DEBUG_SWITCH. Preset strategy assets are only used when enabled in config and build switch permits it; debug builds crash if preset strategy is expected but assets are missing.
AdMob MobileAds.initialize() on Dispatchers.IO. Has explicit isInitComplete() check in loaders in addition to the generic mediation gate.
MAX AppLovinSdk.initialize() using config-supplied sdk key. Debug enables verbose logging; release disables logs. Rewarded loader still uses reflection for constructor access.

10.2 Runtime adapter shape

  • All three families implement the same generic loader/show wrapper contracts across interstitial, rewarded, open, native, and banner.
  • Loaders dispatch paid events, impression/click/close events, and failed-to-show events through shared AdBase plumbing.
  • TopOn banner auto-refresh reuses the same load-success path as initial load.
  • TopOn open ads are displayed through a dedicated TopOnOpenActivity, not directly in-place.

10.3 TopOn-specific runtime notes

  • Before any TopOn load, the SDK refreshes/sends attribution via TopOnTrafficGrouping.callBeforeTopOnAdLoad().
  • TopOn interstitial and rewarded failed-to-show callbacks are owned by the load-side SDK listeners.
  • TopOn paid-event extraction special-cases AdMob-backed fills inside TopOn by reading extInfoMap precision/currency/value-micros.

11. Analytics, Revenue, Attribution

11.1 Emission layers

Layer Examples When it fires
Core ad trackers adv_res, adv_show, adv_click, adv_hide, adv_revenue, adv_adpv Load, impression, click, close, revenue, show-call success/failure.
Infrastructure/base error_detection, biz_remote_config_recv, poseidon_config_version_report Parse failures, config delivery, config promotions.
Business analyzers CMP, CTR, notification preload, TopOn traffic grouping, Adjust attribution, ADPV gap, per-unit response Subsystem-specific side effects.

11.2 Revenue path

  • Paid events flow through AdBase.dispatchOnPaidEvent().
  • That emits ad-revenue analytics, Adjust ad-revenue, Firebase revenue, Adjust impression tokens, cumulative revenue threshold tracking, and then asynchronously persists a revenue row.
  • After a successful revenue insert, the SDK evaluates AEO and RRC ROAS rules.

11.3 AEO and RRC ROAS

  • AEO. One-shot threshold rules over revenue rows within a first-open hour window and filtered by ad types; fires Adjust token and/or Firebase event then stores a boolean flag.
  • RRC ROAS. Two rule families: ARPU thresholds within first-open hour windows and single-impression eCPM thresholds; each rule is one-shot via SharedPreferences.

12. Crypto, Native Identity, And Offline Companions

  • Android cryptor bridge: com.poseidon.ad.main.strategy.cryptor.Cryptor.
  • Native library name: PoseidonCypt.
  • Rust core implements AES-256-CBC with fixed compiled key and fixed IV.
  • The same native core also exports CRC32-based deterministic traffic sampling.
  • Desktop/CI companion module exposes the same encrypt/decrypt behavior through a desktop JAR that loads packaged native binaries.
  • JNI symbol identity is tied to the current package/class names, so clone work must change both crypto material and JNI/native identity.

13. Source-Verified Edge Cases And Corrections

  • Cache expiry is currently hardcoded to 3000000L ms (50 minutes), not remote-controlled.
  • modeDefault="delay" without a modeDelay block falls back to serial queueing.
  • NativeMixOpenAdActivity is currently miswired and exits before rendering.
  • Shared-pool request-count gating increments on request start, not only on success.
  • Fullscreen show-limit rows are created before bidder selection but only marked shown from the actual impression callback path.
  • Notification and new-user fullscreen caches do not enforce readiness at consume time the same way the main/shared/automation/backup pools do.
  • Fullscreen interval-day math uses system timezone; unified frequency counters use Beijing day keys; CTR daily reset uses local-date helper.
